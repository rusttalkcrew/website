RustTalk is gratis, versleutelde spraak-, video- en tekstchat die je zelf draait. Geen accounts, geen advertenties, geen tracking. Berichten en gesprekken zijn end-to-end versleuteld, zodat zelfs de server niet kan meelezen.

Vroege ontwikkeling. RustTalk verandert elke dag. Reken op bugs en af en toe een update die oudere apps moeten installeren voordat ze weer verbinding kunnen maken. De versleuteling is nog niet onafhankelijk geaudit. Gebruik het met vrienden en vertrouw er niet op waar een fout echt schade zou doen.

Als het gratis is, ben jij het product.
Hier niet.

De meeste chatapps kosten niets omdat je betaalt met je data: met wie je praat, wanneer, hoe vaak en hoe lang. Daar hebben wij geen zin in. Achter RustTalk zit geen verdienmodel met jouw data en er valt niets te verkopen. De code is open, de server is van jou en wat je schrijft of zegt, wordt al op je apparaat versleuteld. Weer baas zijn over je eigen data zou geen project voor experts moeten zijn. Het zou normaal moeten zijn.

Jouw server, jouw regels Jij bepaalt wie erbij mag, wat er wordt bewaard en hoe lang.
Niets te verkopen Geen advertenties, geen analytics, geen profielen. Er is niemand aan wie je data wordt verkocht.
Open, niets verborgen Elke regel code is openbaar. Iedereen kan nagaan wat RustTalk doet.

Alles wat een groep nodig heeft

Een native desktopapp in Rust, en een server die je zelf draait met Docker.

Heldere spraak

Opus-audio met ruis- en echo-onderdrukking en automatisch volume. Push-to-talk of spraakactivering.

Scherm & camera

Deel een scherm of één venster, met het geluid van de apps die jij kiest. Tegelijk je camera.

Kanalen & DM's

Tekstkanalen en privéberichten, met geschiedenis, antwoorden en bewerken.

End-to-end versleuteld

Berichten, bestanden, gesprekken en zelfs namen. De server ziet alleen versleutelde data, plus leden, IP-adressen en tijdstippen.

Geen account

Je identiteit is een herstelzin van 24 woorden. Geen e-mail, geen telefoonnummer. Gesynchroniseerd op al je apparaten.

Rollen & moderatie

Rollen, kicken, bannen en een auditlog. Wie verwijderd is, leest geen nieuwe berichten meer: de sleutels veranderen.

Bestanden delen

In chats, gesprekken en DM's. Versleuteld opgeslagen met limieten en verloopdatum, of live verstuurd en nooit opgeslagen.

Ondertekende updates

De app installeert ondertekende updates met één klik. De server werk je bij door nieuwe Docker-images op te halen.

Raid vanavond om 8?

Verwijderde leden en apparaten krijgen de volgende sleutel niet.

Kanaalsleutels reizen tussen apparaten in verzegelde enveloppen die alleen het ontvangende apparaat kan openen.

In gewone woorden

  1. Jij bent je herstelwoorden. Bij de eerste start ontstaan 24 woorden waaruit je persoonlijke sleutel ontstaat, je identiteit. Ze worden nergens opgeslagen, ook niet op je eigen apparaat.
  2. Elk apparaat krijgt eigen sleutels. Je persoonlijke sleutel ondertekent ze, zodat vrienden kunnen controleren dat een apparaat echt van jou is. Apparaat kwijt? Verwijder het met je herstelwoorden.
  3. Elke server en elk kanaal heeft een eigen sleutel. Je app maakt die sleutels en geeft ze aan iedereen die erin mag, telkens in een verzegelde envelop die alleen dat apparaat kan openen (HPKE, RFC 9180).
  4. Alles wordt vergrendeld voordat het je apparaat verlaat. Berichten, bestanden, afbeeldingen, namen, onderwerpen, avatars en emoji worden versleuteld met XChaCha20-Poly1305 en ondertekend met je apparaatsleutel. Spraak, video en schermdelen worden beeld voor beeld versleuteld.
  5. Wie vertrekt, blijft buiten. Na een kick, een ban of een verwijderd apparaat krijgt het kanaal een nieuwe sleutel die zij niet ontvangen. Ze houden alleen wat ze al gezien hebben.

Wat de server wel ziet

Wie lid is, welk apparaat wanneer iets stuurde, hoe groot het is en wie met wie een DM heeft. De sleutels krijgt hij nooit.

Waartegen het niet beschermt

Een server die je niet vertrouwt, kan nog steeds mensen die hij beheert aan een kanaal toevoegen. Daarom toont de app elk nieuw lid en apparaat met zijn vingerafdruk. Sommige details zijn nog niet af, zoals het aanmelden koppelen aan de TLS-verbinding.

Alle releases

Host je eigen server

Een kleine Linux-VPS is genoeg voor een vriendengroep. De installatie is een handvol commando's.

Wat je nodig hebt

Een Linux-server met Docker en een publiek IPv4-adres. Open de poorten 443/tcp, 7881/tcp en 7882/udp, en 80/tcp als je een domein gebruikt. Een domeinnaam die naar de server wijst is optioneel: daarmee krijg je een normaal certificaat. Zonder domein maakt de server zijn eigen certificaat en vertelt de uitnodigingslink de app dat die het kan vertrouwen.

Thuis hosten? Veel internetaansluitingen (DS-Lite of CGNAT) hebben geen publiek IPv4-adres. Dan werkt port forwarding niet. Vraag je provider om een publiek IPv4-adres of gebruik een kleine VPS.

Bestanden ophalen

git clone https://github.com/rusttalkcrew/rusttalk-next.git
cd rusttalk-next/deploy

Instellen

Kopieer de voorbeeldinstellingen en bewerk daarna .env: zet RUSTTALK_IP op het publieke IP-adres van de server en LIVEKIT_API_SECRET op een willekeurig geheim uit openssl rand -hex 32. Met een domein stel je ook RUSTTALK_DOMAIN in.

cp .env.example .env
openssl rand -hex 32

Starten

docker compose pull && docker compose up -d --wait

Claim je server

Toon je eigenaarsuitnodiging en open die in de RustTalk-app. Houd hem privé: wie hem als eerste gebruikt, wordt eigenaar van de server. Gebruik de laatste regel die bij jouw opzet past en vul je IP-adres of domein in.

code=$(docker compose exec -T api rusttalk-api owner-invite)
id=$(docker compose exec -T api rusttalk-api server-id)
pin=$(docker compose logs --no-log-prefix cert | sed -n 's/^TLS pin: //p' | tail -1)
echo "rusttalk://<ip>/i/$code#$id.$pin"   # IP-only mode
echo "rusttalk://<domain>/i/$code#$id"    # domain mode

Later bijwerken

Maak eerst een back-up (zie de volledige gids). Zet RUSTTALK_VERSION in .env op de nieuwe versie, check de bijbehorende release uit en voer dan uit:

docker compose pull && docker compose up -d --wait

Draai je al Caddy, nginx of Traefik op poort 443? Draai achter je eigen reverse proxy.
